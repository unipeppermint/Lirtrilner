# 发条修理铺产品方案

首版以完整免费解谜游戏上线。玩家在复古玩具修理铺里滑动零件、完成订单，让发条机器人、小火车与音乐盒恢复运作。核心体验是规划合并与交付顺序，再看到具体的修复成果。

## 用户与体验目标

面向喜欢合并、空间规划和轻解谜的普通休闲玩家。目标单局时长 2～5 分钟；这是设计目标，需要实测调整。采用温暖的玩具题材，但不据此定位为儿童专属产品。

新玩家第一次进入直接体验第 1 关，在引导内完成一次局部滑动、一次合并和一次交付。完成后进入工坊主页；已完成的新手引导可在设置中重看。

与标准 2048 的主要区别为局部行列操作、精确等级订单、地形约束与可预测补给。这些机制必须实际改变解题策略，视觉主题负责让结果更有吸引力。

## 首版功能范围

| 编号 | 功能 | 发布要求 |
| --- | --- | --- |
| P01 | 工坊主页 | 继续维修、主线关卡选择、每日挑战、收藏与设置入口 |
| P02 | 主线关卡 | 3 章共 36 关，全部配置完成且经解法验证 |
| P03 | 零件合并 | 2 种类型 × I～IV 四级，规则一致 |
| P04 | 精确交付 | 按零件类型和等级核对订单，数量清晰显示 |
| P05 | 修复收藏 | 12 件玩具，每件 3 个维修阶段，最终完成后入收藏 |
| P06 | 每日挑战 | 独立 30 题固定题库，按日期循环，完成记录本地保存 |
| P07 | 辅助功能 | 免费提示、撤销、重开、规则手册 |
| P08 | 自动续玩 | 主线与每日挑战分别保存未完成局；切后台与重启恢复 |
| P09 | 设置 | 音效、音乐、触觉、规则、隐私、支持、版本与重置进度 |

首版不加入付费章节、广告、体力、货币、抽卡、账号、社交、排行榜或云同步。闸门机制延后，第三章通过现有规则组合提升难度。关卡按进度解锁，不设置任何付费解锁入口。

## 棋盘与操作规则

棋盘由 5×5 个格子组成。格子拥有独立地形和零件占用状态；普通格和交付格可容纳零件，障碍格不可进入。首版每关一个交付格，可以处理多种订单。

| 操作或情况 | 明确规则 |
| --- | --- |
| 选择轨道 | 手指起点所在格确定候选行列，方向锁定后只操作对应行或列 |
| 滑动 | 向该方向尽量移动；固定障碍将行列分为互不穿越的片段 |
| 合并条件 | 类型、等级均相同才能合并，I+I→II，II+II→III，III+III→IV |
| 合并次数 | 本次操作生成的零件不能再次参与同次合并；IV 不继续合并 |
| 顺序 | 从移动方向的前端依次处理相邻零件 |
| 有效操作 | 至少一个零件位置或等级改变，才扣除一步 |
| 无效操作 | 不扣步、不推进补给、不写入撤销历史，给轻反馈 |
| 交付 | 零件停在交付格且符合未完成订单，用户点击后消耗并完成一个需求 |
| 不匹配 | 显示需要的类型和等级，不消耗零件、不扣步 |
| 交付选择 | 多个相同需求按订单列表顺序满足，不允许重复计数 |
| 步数 | 只对有效滑动扣步；交付不扣步 |
| 撤销 | 撤销最近一次有效滑动或交付，恢复相关的完整状态 |
| 重开 | 恢复本关初始棋盘和补给序列，已获得的长期收藏保持不变 |

补给由关卡明确指定零件和入口。每次有效滑动结束后尝试投放一枚；入口堵塞时保留同一枚并标记等待，不累计多次投放机会。下一次有效滑动再尝试该枚；若玩家交付清空入口，交付后立即重试一次等待中的补给。一次指令最多投放一枚，投放后指针前进。补给耗尽后不再产生新零件。

当订单全部完成时立即成功。剩余步数为零时禁止再滑动，但若当前可以交付，保留交付操作；交付后再判断是否通关。不能交付且无剩余步数时失败。仍有步数却完全不存在有效滑动或合法交付时判为卡住。求解器超时不能作为无解或失败依据。

失败面板提供撤销、重开与返回。完成后的局面进入结算，不再对已记入收藏的结果开放撤销；允许重新挑战，且不会重复增加收藏。

## 内容结构与计数

每件玩具对应连续 3 个维修关卡，依次完成检查组装、核心维修、试运行。前两关呈现阶段进展，第三关才播放完整恢复动画并增加一个收藏。12 件玩具 × 3 关 = 36 个主线关卡。

| 章节 | 关卡 | 4 件玩具 | 教学和难度重点 |
| --- | --- | --- | --- |
| 初识工坊 | 1～12 | 发条机器人、小火车、旋转音乐盒、螺旋桨飞机 | 第 1 关局部滑动，第 2 关精确交付，第 3 关固定障碍，之后加入电池与补给 |
| 零件之间 | 13～24 | 发条小鸭、玩具相机、小汽车、跳舞小熊 | 双类型订单、入口管理、避免过度合并 |
| 完整收藏 | 25～36 | 小鼓手、木马、机械小狗、小小摩天轮 | 路线冲突、IV 级零件、多个需求的顺序规划 |

章节边界按每 4 件玩具划分。上表内容已按 36 关与 12 件玩具实现，每关包含独立配置及通过重放的参考解。步数预算与难度曲线仍需独立真人试玩验收，见实施报告。

计数固定为“主线进度 x/36”“修复收藏 x/12”“本件维修 x/3”。每日挑战独立记录，不增加主线进度或玩具收藏。复玩关卡只更新个人最佳步数。

## 每日挑战

完成第 3 关后开放，每天一题。题库包含 30 个经过验证的独立谜题，循环使用，界面注明“题库循环”，不宣传每日永久新内容。

使用公历、本地日期和稳定题库顺序选择题目，不使用 Swift 的随机化 hash。当天首次进入后固定当天关卡 ID 与内容版本；跨日时保留昨天未完成局为可继续项目，并提供开始今日挑战入口。设备改时可能改变题目，首版没有排名，不增加反作弊系统。

## 页面与用户流程

首次启动 → 引导关卡 → 阶段结算 → 工坊 → 继续维修 → 完成第三阶段 → 玩具修复动画 → 收藏解锁 → 下一件玩具。

日常启动优先恢复工坊；“继续维修”进入主线存档。每日挑战使用独立入口与存档，切换模式不会覆盖另一模式。

收藏页展示已完成、维修中和待解锁状态。已完成玩具可查看大图、维修记录和重播完成动作；未解锁状态解释进度条件，不展示价格。全部通关后主页显示“收藏完成”，保留复玩和每日挑战入口，隐藏不存在的下一关。

## 体验与质量验收

首次教学可重看、无强制账号、离线完成全部核心功能。用户能辨认零件类型和等级，理解交付原因，失败后有直接恢复路径。

所有提示均免费。提示先解释规则，操作建议必须来自当前局面的已验证后续解；搜索未找到结果时使用“暂未找到通关路线，可撤销或重开”，不得把结果未知说成绝对无解。

进行至少 5 人的独立试玩，记录教学完成、误触、首三关卡点和提示使用情况。首 3 关应能在无现场指导下完成；若重复出现同一规则误解，先修订教学再扩展内容。试玩记录用于内部改进，不等同于线上留存数据。

## 差异化与审核展示

核心差异应在前 3 关可见，商店截图优先展示局部滑动、订单交付和维修成果。采用原创或具备合法使用权的玩具形象、音效和界面素材。后续内容在同一应用中更新。

苹果审核关注仿冒、最低功能、重复应用及难以区分的体验；本产品通过可体验的规则与内容形成差异，不能承诺通过审核。[Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/#design)
